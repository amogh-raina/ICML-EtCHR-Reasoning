# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

Research code and data for an ICML Workshop paper on how well LLMs reason about **ECtHR (European Court of Human Rights) Article 10 (freedom of expression)** cases. Everything is scoped to cases that have a violation / non-violation finding on Article 10 or discuss it.

Given a case's facts, a generator LLM (GPT-5.4 via OpenRouter) writes a step-by-step legal assessment and a yes/no violation prediction. Three prompting strategies are compared:

| Key (folder/field name) | Paper label | Prompt file |
|---|---|---|
| `non_curated` | A: Non-Curated | `Prompts/Non-Curated_prompt.txt` |
| `instruction` | B: Curated (Expert), a 4-step scaffold: interference / prescribed by law / legitimate aim / necessary in a democratic society | `Prompts/Instruction_prompt.txt` |
| `gpt_assisted` | C: Curated (Guide), a strategy generated by an LLM from the Art. 10 case-law guide (`data/guide_10.txt`) | `Prompts/gpt_assisted_prompt.txt` |

Assessments are scored on 4 reasoning steps (per step: `occurrence` 0/1, `comprehensiveness` 1-5) plus `overall_conciseness` (1-5), by three LLM judges (GPT-5.5, Claude Opus 4.7, DeepSeek V4 Pro) and by three human annotators. The repo also measures violation-prediction accuracy, citation usage/ordering, factual-paragraph references and token cost.

Use the strategy keys above (`non_curated`, `instruction`, `gpt_assisted`) exactly as written. They are the folder names and JSON keys everywhere.

## Setup and running

- `pip install -r requirements.txt` (`openai`, `python-dotenv`, `numpy`, `matplotlib`, `requests`, `tqdm`; the rest is stdlib, and the xlsx reader and Krippendorff α are hand-rolled).
- The API scripts read `OPENROUTER_API_KEY` from a `.env` in the repo root; copy `.env.example` to `.env` and fill it in (everything goes through OpenRouter using the `openai` client). Only the scripts that call an LLM need it: `run_pipeline.py`, `run_eval.py`, `run_guideline.py`. All analysis/plotting scripts run offline on files already in the repo.
- **The parsed dataset is not in git.** Download `parsed_cases_all(3,9,10,11).json` from the Google Drive link in the README and place it at `data/parsed_cases_all(3,9,10,11).json`. Every script that touches case text (`run_pipeline.py`, `run_eval.py`, `eval_*.py`, `build_annotation_csvs.py`, `dataset_stats.py`) fails without it. The annotators' `.xlsx` workbooks are also distributed through the Drive link, not git.
- **Untracked (author's local copies only):** the raw HUDOC downloads `data/html/`, `data/json/`, `data/art3/{html,json}` (needed only to re-run `scraping/parse_cases.py`), `data/parsed_cases(9,10,11).json`, `data/art3/parsed_cases(3).json`, `data/old_cases.json`, `data/annotation/archive_annotations/`, `Paper/`, `appendix*.tex`, `chat_notes.txt`, and a few superseded files. If something described below is missing from a fresh clone, it is one of these.
- Run every script **from the repo root**. Paths are derived from `Path(__file__).parent.parent`, so scripts work from any cwd, but the CLI examples below assume root.
- There is no test suite or linter.
- Note the mixed-case folder names: `Paper/ Prompts/ Runs/ Scripts/` are capitalised, `data/` and `scraping/` are lowercase.

Most scripts have their configuration as constants at the top of the file (model, reasoning effort, input/output dirs). To re-run an experiment under different settings you usually edit those constants, not pass flags.

```bash
# Generate predictions (model/effort/output dir are constants in the file; flags: --model --effort --api-key)
python3 Scripts/run_pipeline.py

# Judge one pair of strategies (judge model is the MODEL constant in the file)
python3 Scripts/run_eval.py --dir-a Runs/outputs_new --prompt-a instruction \
    --dir-b Runs/outputs_gpt_assisted --prompt-b gpt_assisted \
    --output-dir "Runs/outputs_eval_(instructions vs gpt_assisted)_gpt5.5"

# Post-process responses: extract `citations` + `ref_paragraphs` into each response.json (dry run without --write)
python3 Scripts/add_citations.py --write

# Recompute the evaluations (each writes into its own data/<x>_eval/ folder)
python3 Scripts/eval_violation_prediction.py
python3 Scripts/eval_token_usage.py
python3 Scripts/eval_citations.py
python3 Scripts/eval_ref_paragraphs.py
python3 Scripts/compute_eval_scores.py        # judge outputs -> data/judge_eval_summary/
python3 Scripts/compute_agreement.py          # human IAA + judge-vs-human -> data/agreement/
python3 Scripts/build_overall_results_table.py
```

## Repository map

### `data/`: dataset and all computed results

**Source data (scraped from HUDOC)**
- `html/`, `json/` (untracked): raw HUDOC case text (`html/<id>.html`) and metadata (`json/<id>.json`) for Articles 9/10/11 (43 cases). `art3/{html,json}` (untracked) plus `art3/parsed_cases(3).json` is the same for Article 3.
- `case_ids(9,10,11).tsv`, `case_ids(3).tsv`: the HUDOC item ids that were scraped.
- `parsed_cases_all(3,9,10,11).json` (**gitignored, get it from the Drive link**): **the canonical dataset**, the output of `scraping/parse_cases.py` over both html dirs. It is the only parsed file any script reads. Every experiment loads it and keeps only cases with an Article 10 court assessment, which gives **29 cases** (`c["court_assessments"][i]["articles"]` contains `10`; see `load_art10_cases()` in `Scripts/run_pipeline.py`). `parsed_cases(9,10,11).json` is an earlier subset without Art. 3 and is not read by any script.
- `guide_10.txt`: the ECtHR Article 10 case-law guide, injected into the guideline-generation prompt.

**Human annotations: `data/annotation/`**
- `A_*.csv`, `B_*.csv`, `C_*.csv`: annotation sheets per strategy pair (A: instruction vs non_curated, B: instruction vs gpt_assisted, C: gpt_assisted vs non_curated), built by `Scripts/build_annotation_csvs.py`. Columns hold facts, court assessment, citations, both responses, empty rating columns, and `A_category`/`B_category` saying which strategy produced each side.
- `combined_30_seed42_og.csv`: **the annotation manifest.** A seeded sample of 30 rows (case × strategy-pair) covering **22 distinct cases** (some cases appear 2-3× under different pairs), with `swapped` recording whether the A/B display order was flipped. It serves as (a) the row-order key for aligning the human JSON arrays and (b) the definition of the annotated case set, which `eval_violation_prediction.py`, `eval_token_usage.py` and `eval_ref_paragraphs.py` filter to.- `Annotation Guidelines.pdf` is the rubric the annotators were given. Their filled-in `.xlsx` workbooks are not tracked (see the Drive link); `convert_human_annotations.py` already turned them into the `human_*_annotations.json` files below, so it only needs re-running if the workbooks change.
- **`human_1_annotations.json`, `human_2_annotations.json`, `human_3_annotations.json`**: one per annotator, produced by `Scripts/convert_human_annotations.py`. Shape: `{strategy: {step_1..step_4: {occurrence: [...], comprehensiveness: [...]}, overall_conciseness: [...]}}`, with 20 values per list. The arrays are ordered by walking `combined_30_seed42_og.csv` in row order, **side A then side B**, appending to the list for that side's strategy. That walk is the only link from an array position back to `(item_id, strategy)`; `compute_agreement.py` replays it.
- **`human_annotations.json`**: the three annotators concatenated (list order 1, 2, 3, so 60 values per list). It is only produced when `convert_human_annotations.py` is run with `--merge-output`. Used for the pooled human numbers in `build_overall_results_table.py`, `plot_human_scores.py` and `build_combined_heatmaps.py`.
- `plots/`: human-vs-judge step heatmaps (png/pdf).

**LLM judges and annotations are independent.** `run_eval.py` never reads anything in `data/annotation/`. It judges every one of the 29 cases' outputs from `Runs/` against the court's Merits text. Annotations only enter later, in `compute_agreement.py` (via `judge_eval_summary/long_rows.csv`) and in the plots/tables.

**Computed results (all regenerable from the scripts; don't hand-edit)**
| Folder | Produced by | Contents |
|---|---|---|
| `judge_eval_summary/` | `compute_eval_scores.py`, `plot_judge_scores.py` | `long_rows.csv` (one row per case × side × judge-folder), `aggregates.json`, `plots/` |
| `agreement/` | `compute_agreement.py` | `agreement.json`, `agreement_tables.md` (human IAA, judge↔human ρ/bias, judge–judge α) |
| `violation_eval/` | `eval_violation_prediction.py` | prediction vs ground truth per (case, strategy) |
| `token_usage/` | `eval_token_usage.py` | reasoning / output / completion tokens per (case, strategy) |
| `citation_eval/` | `eval_citations.py` | cited-case-law order vs court's (Kendall τ / Spearman ρ, extras) |
| `refparagraph_eval/` | `eval_ref_paragraphs.py` | fact-paragraph references vs court's (P/R/F1, groundedness) |
| `results_overall_table/` | `build_overall_results_table.py` | `overall_results.csv`, `overall_results_table.tex` (paper Table 1) |

### `scraping/`
`case_metadata.py` (HUDOC json) and `case_text.py` (HUDOC html) download the raw files; `parse_cases.py` turns html + json into `parsed_cases_all(3,9,10,11).json` (Articles 3, 9, 10, 11; also exports `extract_citations`, reused by `Scripts/add_citations.py`); `dataset_stats.py` prints corpus statistics (`python3 -m scraping.dataset_stats`). The two downloaders read `data/case_ids.tsv` and stop after `max_count = 100`. That filename doesn't exist any more (see the two `case_ids(...)` tsv files), so rename or edit before re-scraping.

### `Prompts/`
The prompts, as plain text. `Instruction_prompt.txt`, `Non-Curated_prompt.txt`, `gpt_assisted_prompt.txt` are the three generator prompts; `judge_prompt.txt` is the judge rubric (four `{}` placeholders: case facts, court Merits, Response A, Response B). `asssessment_without_guideline_prompt.txt` (sic) and `extract_assessment_from_guideline_prompt.txt` are the prompts for the guideline-generation experiment below. `run_pipeline.py` splits each generator prompt at its "Relevant Case Law" header: the part before is the fixed system message, and the per-case facts and shuffled citation list are appended.

### `Runs/`: all raw LLM outputs
Per-case layout: `Runs/<run>/<item_id>/<strategy>/{response.json,reasoning.txt}`.

- **Predictions:** `outputs_new/` (GPT-5.4, `instruction` + `non_curated`, reasoning effort `medium`) and `outputs_gpt_assisted/` (GPT-5.4, `gpt_assisted`, effort **`high`**), both 29 cases. **These two are what every downstream script reads.** `outputs_mistral/` is Mistral Medium 3.5 on `instruction` + `non_curated` (a robustness check that no downstream script reads), and `outputs_mistral_eval_gpt5.5/` is GPT-5.5 judging those outputs.
- **Judge outputs:** `outputs_eval_(<A> vs <B>)_<judge>/<item_id>/response.json`. There are 3 pairs × 3 judges (`gpt5.5`, `claude`, `deepseek`) = 9 folders, plus `outputs_mistral_eval_gpt5.5/`. Response A / Response B in a folder name are the strategies compared. **Folder names are parsed by regex in `compute_eval_scores.py`**, which tolerates the existing inconsistencies (`vs` vs `_vs_`, `instruction` vs `instructions`, `non-curated` vs `non_curated`). Keep that naming style, or update the regex, when adding new judge runs.
- **Guideline-generation experiment:** `outputs_guideline/` (v1, GPT-5.4), `_v2` (DeepSeek), `_v3` (Gemini), `_v4` (GPT-5.4), `outputs_no_guideline/`. Each holds a single `response.json` + `reasoning.txt`: a case-agnostic assessment strategy generated from `guide_10.txt` (or without it). These are **not** fed into `run_pipeline.py`. `Prompts/gpt_assisted_prompt.txt` was written by hand from the **v4** output, so v4 is the provenance of strategy C.

### `Scripts/`
- **Generate:** `run_pipeline.py` (predictions), `run_guideline.py` (guideline/strategy generation; default → `outputs_guideline_v4`, `--no-guideline` → `outputs_no_guideline`), `run_eval.py` (judge).
- **Post-process / evaluate:** `add_citations.py`, `eval_violation_prediction.py`, `eval_token_usage.py`, `eval_citations.py`, `eval_ref_paragraphs.py`, `compute_eval_scores.py`, `compute_agreement.py`.
- **Annotation plumbing:** `build_annotation_csvs.py` (makes A/B/C csvs and the seeded combined sample; `--n-per-run`, `--seed`, `--combined-only`), `convert_human_annotations.py` (xlsx → human_N json).
- **Figures / tables:** `plot_judge_scores.py`, `plot_human_scores.py`, `build_combined_heatmaps.py`, and `build_overall_results_table.py`.

## Data formats

**`parsed_cases_all(3,9,10,11).json`** is a list of cases: `item_id`, `case_number`, `case_name`, `date`, `section`, `facts` (list of numbered paragraph strings), `violation` (list of article codes the court found violated, e.g. `["10", "10-1"]`; **empty or other-article codes mean no Art. 10 violation**), `conclusion`, `court_assessments`. Each `court_assessments` entry has `articles` (list of ints) and `subsections`: `{subsection_title, paragraphs, ref_paragraphs, citations}`. Titles are `Admissibility` and `Merits`; Grand Chamber cases title the Art. 10 analysis `General`. The court's assessment for evaluation = the Art. 10 Merits (or `General`) subsections. Entries with `error` / `empty_file` set are skipped.

**Prediction `response.json`:** `item_id, case_name, case_number, date, prompt_type, model, reasoning_effort, violation_ground_truth, violation_prediction ("yes"/"no"), assessment` (list of `{step_title: step_text}`), `raw_content, usage`, plus `citations` and `ref_paragraphs` after `add_citations.py`. The `reasoning.txt` beside it is only the provider's returned reasoning *summary*; it is empty for many calls even though reasoning tokens were billed, so use `usage` (`completion_tokens_details.reasoning_tokens`) for real cost.

**Judge `response.json`:** `item_id, case_name, model, reasoning_effort, raw_content, usage` and `parsed.evaluation`: `[{"student_a": [{"step_1": {"occurrence", "comprehensiveness"}}, ..., {"overall_conciseness"}]}, {"student_b": [...]}]`. Judges sometimes emit inconsistent JSON shapes; `compute_eval_scores.py` has the tolerant parser, so reuse it rather than reading `parsed` directly.

## Things that are easy to get wrong

- **Case-set sizes differ by stage.** Predictions/judging cover 29 cases; the human-annotated set is 22 distinct cases (30 case×pair rows); the accuracy/token/paragraph evals filter to those 22 via `combined_30_seed42_og.csv`. `compute_eval_scores.py` **excludes the three Grand Chamber cases** (`001-244292`, `001-247738`, `001-247839`) from `long_rows.csv`, though two of them are in the annotated set, so those items have no judge rows to match in `compute_agreement.py`.
- **Violation ground truth is per-Article-10, not per-case.** `eval_violation_prediction.py` maps `violation` to `gt_art10` ("yes" iff any code has base article 10). Cases whose `violation` is empty or lists other articles are valid Art. 10 "no violation" cases.
- **Stale paths in a few scripts.** `run_guideline.py` reads `Runs/guideline_prompt.txt` and `Runs/no_guideline_prompt.txt`, which no longer exist. The prompt texts now live in `Prompts/extract_assessment_from_guideline_prompt.txt` and `Prompts/asssessment_without_guideline_prompt.txt`, so update the two path constants first. In `run_pipeline.py` the `gpt_assisted` entry of `PROMPT_FILES` is commented out and points at `Runs/gpt_assisted_prompt.txt`; the file is now `Prompts/gpt_assisted_prompt.txt`. Docstrings in `run_pipeline.py`/`run_guideline.py` mention `Runs/run_*.py`; the scripts live in `Scripts/`.
- **`run_pipeline.py` defaults do not write to `outputs_new/`**; `OUTPUT_DIR` is currently `Runs/outputs_new_gpt-5.4` (an untracked re-run), so change the constant if you want downstream scripts to see new predictions. Downstream scripts also expect the `citations`/`ref_paragraphs` fields that `add_citations.py --write` adds to those responses. It also skips (case, strategy) pairs whose `response.json` already exists.
- **`data/results_overall_table/overall_results.csv` can lag** behind `violation_eval/` (it was generated when accuracy was computed on a different case subset). Re-run `eval_violation_prediction.py` then `build_overall_results_table.py` to refresh it.
- **Strategy C was run at higher reasoning effort** (`high` vs `medium` for A/B), so its comparison against A/B is confounded by compute.
